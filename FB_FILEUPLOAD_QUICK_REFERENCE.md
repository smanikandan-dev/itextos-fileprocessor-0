
## 🎯 Common Use Cases

### Use Case 1: Single CSV Upload

```
Scenario: Upload contacts list (50,000 records)
File: contacts.csv (5MB)

Request:
  POST /save
  - username: john_doe
  - frompage: campaign
  - file: contacts.csv

Process:
  1. Upload: ~1 second
  2. UTF-8 convert: ~0.5 seconds
  3. Count records: ~0.5 seconds (async)
  4. Track in Redis: ~0.1 seconds
  Total: ~2 seconds

Response:
  {
    "total": 50000,
    "total_human": "50K",
    "uploaded_files": {
      "success": [{
        "filename": "contacts.csv",
        "count": 50000
      }]
    }
  }
```

### Use Case 2: ZIP with Multiple Files

```
Scenario: Upload ZIP with 3 CSV files
File: campaigns.zip (15MB)
  ├── file1.csv (5MB, 50K records)
  ├── file2.csv (5MB, 50K records)
  └── file3.csv (5MB, 50K records)

Request:
  POST /save
  - username: john_doe
  - frompage: campaign
  - file: campaigns.zip

Process:
  1. Upload: ~2 seconds
  2. Extract ZIP: ~1 second
  3. Convert 3 CSVs: ~1.5 seconds
  4. Count (parallel): ~0.5 seconds
  5. Track: ~0.1 seconds
  Total: ~5 seconds

Response:
  {
    "total": 150000,
    "total_human": "150K",
    "uploaded_files": {
      "success": [
        {"filename": "file1.csv", "count": 50000},
        {"filename": "file2.csv", "count": 50000},
        {"filename": "file3.csv", "count": 50000}
      ]
    }
  }
```

### Use Case 3: Large XLSX File


## 🔀 Process Flow Comparison

### CSV vs XLSX Processing

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      CSV FLOW                                            │
└─────────────────────────────────────────────────────────────────────────┘

Upload → Store Temp → UTF-8 Convert → Store Final → Count (Stream)
  1s        0.5s          0.5s           0.5s          0.5s
                                                          │
  Total: ~3 seconds                                      ▼
                                                      Response

Memory: Constant (~10MB)
Process: Line-by-line reading
Benefit: Fastest, most efficient


┌─────────────────────────────────────────────────────────────────────────┐
│                      XLSX FLOW                                           │
└─────────────────────────────────────────────────────────────────────────┘

Upload → Store → Open Package → Setup SAX → Parse (Events) → Count
  5s      1s         1s           1s          20s              │
                                                               ▼
  Total: ~28 seconds                                       Response

Memory: Constant (~20MB)
Process: SAX events (startElement, endElement, characters)
Benefit: Can handle huge files without loading all into memory


┌─────────────────────────────────────────────────────────────────────────┐
│                      XLS FLOW                                            │
└─────────────────────────────────────────────────────────────────────────┘

Upload → Store → Load Workbook → Iterate Rows → Count
  3s      1s        5s              15s           │
                    (ALL IN MEMORY)              ▼
                                              Response
  Total: ~24 seconds

Memory: High (= file size)
Process: Full workbook in memory, row iterator
Limitation: ~50MB files max (memory constraint)
```

## 🧵 Threading Model

### Sequential vs Parallel Processing

```
┌─────────────────────────────────────────────────────────────────────────┐
│ SEQUENTIAL PROCESSING (If we didn't use FutureTasks)                    │
└─────────────────────────────────────────────────────────────────────────┘

File 1 (5s) ████████ → File 2 (5s) ████████ → File 3 (5s) ████████
Total Time: 15 seconds


┌─────────────────────────────────────────────────────────────────────────┐
│ PARALLEL PROCESSING (Current Implementation with FutureTasks)           │
└─────────────────────────────────────────────────────────────────────────┘

File 1 (5s) ████████
File 2 (5s) ████████
File 3 (5s) ████████
Total Time: 5 seconds (3x faster!)


Thread Lifecycle:
┌──────────────────────────────────────────────────────────────────┐
│ Main Thread (FilesSaver)                                         │
│   │                                                               │
│   ├─► Create FutureTask 1 → Thread 1 → Parse File 1             │
│   ├─► Create FutureTask 2 → Thread 2 → Parse File 2             │
│   ├─► Create FutureTask 3 → Thread 3 → Parse File 3             │
│   │                                                               │
│   ├─► Push files to Redis (tracking)                            │
│   │                                                               │
│   ├─► Wait loop:                                                 │
│   │     while (!all_tasks_done) {                               │
│   │       check each task.isDone()                              │
│   │       sleep(100ms)                                           │
│   │     }                                                         │
│   │                                                               │
│   ├─► Collect results:                                           │
│   │     for each task {                                          │
│   │       result = task.get()                                    │
│   │       add to success/failed list                            │
│   │     }                                                         │
│   │                                                               │
│   └─► Build response → Send to client                           │
└──────────────────────────────────────────────────────────────────┘
```

```
Naming Convention:
  originalName_UUID.extension

Examples:
  contacts_a1b2c3d4-e5f6-7890-1234-567890abcdef.csv
  leads_12345678-90ab-cdef-1234-567890abcdef.xlsx

Temp Files (CSV only):
  originalName_UUID_timestamp.csv
  Example: contacts_abc123_2024-01-15_120530123.csv
```

### File Lifecycle

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        FILE LIFECYCLE                                    │
└─────────────────────────────────────────────────────────────────────────┘

1. UPLOAD PHASE
   Client → Server
   Stored: /opt/files/campaigns/username/file_uuid.csv

2. TRACKING PHASE
   Redis: tracking:campaign:username
   Value: ["/opt/files/campaigns/username/file_uuid.csv"]

3. PROCESSING PHASE
   fb-initialstage polls DB → Finds campaign → Pushes to queue

4. DOWNSTREAM PHASE
   fb-splitstage → Reads file → Splits → Creates split files
   fb-handoverstage → Reads splits → Sends to Kafka

5. CLEANUP PHASE (fb-cronjobs)
   - Checks campaign status in DB
   - If completed/failed:
     • Deletes original file
     • Deletes split files
     • Removes from Redis tracking

Typical Retention:
  - Successful campaigns: 7-30 days
  - Failed campaigns: 1-7 days
  - Configurable per system
```

## 🔍 Debugging Tips

### Common Issues and Solutions

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Issue: File upload times out                                             │
├──────────────────────────────────────────────────────────────────────────┤
│ Symptoms:                                                                │
│   - Request hangs                                                        │
│   - HTTP 504 Gateway Timeout                                            │
│                                                                           │
│ Causes:                                                                  │
│   1. File too large                                                      │
│   2. Network slow                                                        │
│   3. Server processing slow                                              │
│                                                                           │
│ Solutions:                                                               │
│   1. Increase server timeout:                                            │
│      - WildFly: standalone.xml → socket-binding                          │
│      - Nginx: proxy_timeout                                              │
│   2. Compress file (ZIP)                                                 │
│   3. Split large files into smaller chunks                               │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Issue: "Unsupported File Type" error                                    │
├──────────────────────────────────────────────────────────────────────────┤
│ Symptoms:                                                                │
│   - File uploaded but shows in "failed" list                            │
│   - Error: "Unsupported File Type"                                      │
│                                                                           │
│ Causes:                                                                  │
│   1. File extension not .csv/.xls/.xlsx/.zip                            │
│   2. File corrupted                                                      │
│   3. Incorrect MIME type                                                 │
│                                                                           │
│ Solutions:                                                               │
│   1. Check file extension (case-insensitive)                            │
│   2. Verify file not corrupted:                                          │
│      - Try opening in Excel/LibreOffice                                  │
│   3. Re-export/re-save file                                              │
│   4. Convert to CSV if unsure                                            │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Issue: Count is 0 but file has data                                     │
├──────────────────────────────────────────────────────────────────────────┤
│ Symptoms:                                                                │
│   - Upload succeeds                                                      │
│   - Count returned is 0                                                  │
│   - File actually has rows                                               │
│                                                                           │
│ Causes:                                                                  │
│   1. All rows are empty (blank first column)                            │
│   2. File has headers only                                               │
│   3. Encoding issue (parser can't read)                                  │
│                                                                           │
│ Solutions:                                                               │
│   1. Check first column has data                                         │
│   2. Verify file has data rows (not just header)                        │
│   3. Save file as UTF-8                                                  │
│   4. Remove any hidden characters                                        │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Issue: Response takes too long                                          │
├──────────────────────────────────────────────────────────────────────────┤
│ Symptoms:                                                                │
│   - Request completes but takes minutes                                  │
│   - Multiple files uploaded                                              │
│                                                                           │
│ Causes:                                                                  │
│   1. Large files being counted synchronously                             │
│   2. Many files in single request                                        │
│   3. Server resource constrained                                         │
│                                                                           │
│ Solutions:                                                               │
│   1. Upload files in smaller batches                                     │
│   2. Use ZIP for multiple files (extracts faster)                        │
│   3. Scale up server (more CPU/RAM)                                      │
│   4. Consider async response (webhook)                                   │
└──────────────────────────────────────────────────────────────────────────┘
```

## ✅ Best Practices

### For File Uploads

1. **Use CSV for large files**
   - Fastest processing
   - Lowest memory usage
   - Best for > 1M records

2. **Compress multiple files**
   - Use ZIP for > 5 files
   - Reduces upload time
   - Single request

3. **Validate files before upload**
   - Check format
   - Verify headers
   - Remove empty rows

4. **Use appropriate file names**
   - Descriptive names
   - No special characters
   - System generates UUID anyway

5. **Monitor upload progress**
   - Files tracked in Redis
   - Check logs for status
   - Set reasonable timeouts

### For Developers

1. **Error handling**
   - Catch per-file errors
   - Don't fail entire batch
   - Log detailed errors

2. **Resource management**
   - Always close streams
   - Use try-with-resources
   - Clean up temp files

3. **Testing**
   - Test with large files
   - Test concurrent uploads
   - Test error scenarios

4. **Logging**
   - Log time taken
   - Log file counts
   - Log errors with context

## 🎓 Summary

The **fb-fileupload** module is a robust, efficient file upload handler that:

✅ Supports multiple formats (CSV, XLS, XLSX, ZIP)  
✅ Processes files asynchronously for speed  
✅ Uses streaming for memory efficiency  
✅ Handles errors gracefully  
✅ Tracks files for cleanup  
✅ Scales with load  

**Key Takeaways:**
- CSV is fastest and most efficient
- XLSX uses SAX parsing for large files
- FutureTasks enable parallel processing
- Files tracked in Redis for cleanup
- UTF-8 conversion ensures consistency
